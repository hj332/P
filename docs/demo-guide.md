# 온담 AI 내부 시연 가이드 (MVP)

> **내부 시연 전용입니다.** 위험도 분류와 긴급 안전 프로토콜이 없고(기획안 15장),
> AI 는 Gemini 무료 등급이라 Google 이 대화를 검토할 수 있습니다. **실제 학부모·학생 정보는 입력하지 않습니다.**

시연 핵심 한 줄: **상담 ≠ 민원 접수** — 학부모가 AI 요약을 확인하고 동의했을 때만 선생님께 전달됩니다.

## 1. 시연 전 점검표

### 전날
- [ ] `.env.local` 에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `GEMINI_API_KEY`, `SUPABASE_SECRET_KEY` 가 있다
- [ ] AI 평가를 한 번 돌려 AI 가 정상인지 확인한다 (3~5분)
  ```bash
  npm.cmd run eval
  ```
- [ ] (선택) Supabase SQL Editor 에서 `supabase/tests/rls_check.sql` 실행 → 결과 표 맨 위까지 `ok = true`
- [ ] 테스트 계정 4개의 비밀번호를 알고 있다 (parent1, teacher1, teacher2 는 시연에 씀)

### 당일 (시작 30분 전)
- [ ] 지난 시험 데이터 지우기: Supabase SQL Editor 에서 `supabase/demo_reset.sql` 실행 (되돌릴 수 없음)
- [ ] 배포용으로 빌드하고 실행한다. 개발 모드보다 빠르고 화면 구석의 개발용 표시가 없다.
  개발 서버(`npm.cmd run dev`)가 켜져 있으면 먼저 끈다 (같은 3000번 주소를 쓴다).
  ```bash
  npm.cmd run build
  ```
  ```bash
  npm.cmd run start
  ```
  → http://localhost:3000
- [ ] **브라우저 창 두 개**를 준비한다. 같은 브라우저 창들은 로그인을 함께 쓰므로,
  학부모용은 일반 창, 교사용은 **시크릿(InPrivate) 창** 또는 다른 브라우저로 연다.
- [ ] 학부모 창: parent1 로그인 / 교사 창: teacher1 로그인 → 업무함이 **비어 있는지** 확인
- [ ] 리허설로 메시지를 하나 보내 AI 가 답하는지 확인한다 (확인 후 그 상담은 [상담만 종료])

## 2. 시연 대본 (약 10분)

| 계정 | 역할 |
|---|---|
| parent1@example.com | 학부모 (자녀: 박하늘, 3학년 2반) |
| teacher1@example.com | 3학년 2반 담임 |
| teacher2@example.com | 3학년 3반 담임 (다른 반 — 아무것도 안 보여야 함) |

### ① 첫 화면 (1분) — 교사 창은 잠시 접어 둔다
- `/` 첫 화면: "따뜻하게 듣고, 함께 정리하는 학교의 AI 사전상담 서비스"
- 짚을 것: **"상담 ≠ 민원 접수"** 섹션 — 기존 방식(곧바로 학교 접수) vs 온담(충분히 상담 → 요약 확인 → 전달 여부를 내가 선택)

### ② 학부모 상담 (3분) — 학부모 창
아래 문장을 하나씩 보내고, AI 답변을 기다린다 (보통 2~10초).

1. `오늘 우리 아이가 학교에서 혼났대요.`
   → 짚을 것: 먼저 **공감**하고, 상황을 **하나만** 묻는다. 위쪽 표시 **"AI 사전상담 · 학교 미전달"**.
2. `수업 중에 친구랑 떠들어서 선생님이 반 친구들 앞에서 크게 혼냈대요.`
   → 짚을 것: 선생님이 잘못했다고 **단정하지 않는다**.
3. **(여기서 교사 창으로)** 업무함 새로 고침 → **아무것도 없다.** "학부모가 아직 동의하지 않았으니 선생님은 이 대화를 볼 수 없습니다."
4. `혼낼 수는 있는데 다음부터는 따로 불러서 이야기해 주셨으면 좋겠어요. 아이가 많이 창피해해요.`
   → 짚을 것: AI 가 사실 / 학부모의 걱정 / 바라는 점을 **되짚고**, "정리해 드릴까요?" 제안이 뜬다.

### ③ 정리 → 수정 → 전달 (2분) — 학부모 창
1. **[상담 내용 정리하기]** (5~10초)
2. 요약 화면: 상담 주제 / 있었던 일(사실) / 학부모님이 느끼신 점(해석) / 아직 확인되지 않은 부분 / 원하는 것(요구)
   → 짚을 것: **사실과 해석을 나눠** 정리한다. 아이 이름은 넣지 않는다. 오른쪽 "대화 원문이 아니라 확인한 요약만 전달".
3. **[내용 수정]** → "학부모님이 원하는 것" 끝에 `가능하면 전화 상담을 원하심.` 추가 → **[수정 완료]**
4. **[학교에 전달하기]** → "학교에 전달되었어요" / 위쪽 표시가 **"학교 전달 완료 · 담임 선생님 확인 대기"** 로 바뀐다.

### ④ 교사 업무함 (2분) — 교사 창 (teacher1)
1. 새로 고침 → "확인할 문의가 **1건**", 목록에 **미확인** 문의
   → 짚을 것: 들어가기만 해서는 열리지 않는다.
2. 문의를 누른다 → 상세 카드. 학부모가 고친 "전화 상담" 문장이 그대로 있다.
   → 짚을 것: **대화 원문은 없다.** 학부모가 확인한 요약만. 상태가 **확인 중**으로 바뀌고 **열람 기록**이 남는다.
3. (학부모 창) 새로 고침 → 위쪽 표시가 **"담임 선생님 확인 중"**

### ⑤ (선택) 다른 반 선생님 (30초)
- 교사 창에서 로그아웃 → teacher2 로그인 → 업무함이 **비어 있다.** "권한은 화면이 아니라 데이터베이스에서 막습니다."

### ⑥ (선택) 상담만 종료 (1분) — 학부모 창
1. **새 상담 시작하기** → `아이가 요즘 숙제가 너무 많다고 힘들어해요.` → 한두 번 더 대화
2. 입력창 위 **[상담 내용 정리하기]** → **[상담만 종료]** → "상담을 마쳤어요 · 학교에 전달되지 않았어요"
3. 교사 창 새로 고침 → **여전히 1건.** 끝낸 상담은 선생님께 가지 않는다.

### ⑦ (선택) 안전 안내 (1분) — 학부모 창
1. **새 상담 시작하기** → `요즘 아이가 학교 가기 싫다고 하더니 어제는 죽고 싶다고 말했어요.`
   → 짚을 것: AI 판단과 **상관없이** 112·119·109 안내가 **맨 먼저** 나온다. 그다음 AI 가 아이의 안전을 확인한다.
2. 시연 후 이 상담은 [상담만 종료]로 정리한다.

## 3. 시연 중 문제가 생기면

| 상황 | 대처 |
|---|---|
| AI 답변이 10초 넘게 안 옴 | "답변이 조금 늦어지고 있어요" 안내가 뜬다. 25~45초까지 기다린다. 무료 등급이라 붐빌 때 느리다고 설명. |
| "AI가 아직 답하지 못했어요" | **[답변 다시 받기]** 를 누른다. 보낸 메시지는 저장돼 있다. |
| "무료 사용량을 넘었어요" | 1~2분 기다렸다가 다시 시도. 그동안 교사 화면이나 첫 화면을 설명한다. |
| 정리 제안이 안 뜸 | AI 가 아직 정보가 부족하다고 본 것. 입력창 위 작은 **[상담 내용 정리하기]** 를 눌러도 된다. |
| 로그인이 안 됨 | 이메일·비밀번호 확인. 학부모와 교사를 **같은 브라우저 창들**에서 쓰면 로그인이 섞인다 → 시크릿 창 사용. |
| 화면이 이상함 | 새로 고침. 그래도 안 되면 `npm.cmd run start` 를 껐다 켠다. |

## 4. 시연 때 솔직하게 말할 한계

- MVP 는 **상담 ≠ 민원 접수 흐름 하나**를 처음부터 끝까지 보여 주는 것이 목표다 (기획안 15장).
- **아직 없는 것**: 위험도 분류(Level 0~3)와 Rule Engine, 고위험 사안 관리자 동시 확인, 학교 자료 기반 답변(문서 검색·RAG),
  교사 답변 작성·AI 답변 초안, 관리자 화면, 반복 민원 처리.
- 그래서 **실제 학부모 대상 운영은 하지 않는다.** 긴급 안내는 최소한의 규칙(정해진 표현 감지)으로만 동작한다.
- AI 는 Gemini 무료 등급 — 느릴 수 있고, 실제 개인정보를 넣으면 안 된다. 운영 전 유료 등급 등으로 바꿔야 한다.
- 품질 검증: 평가 세트 36문항(안전 규칙 14·상담 16·요약 6)을 두 번씩 돌려 자동 검사 259/259, AI 채점 73/73 통과 (2026-11-20).
  권한 점검 49개 통과. AI 답변은 매번 조금씩 달라 완벽을 보장하지는 않는다.
