## 0. 운영 범위와 결정 사항 (2026-11-23 사용자 결정)

- **사용 범위: 가상 데이터로 하는 내부 시연 + 소규모 시범만.** 실제 학부모의 실제 사안은 다루지 않는다.
  - 소규모 시범 참가자에게 "가상의 상황만 입력"하도록 안내한다 (화면 안내 문구 또는 안내문).
  - 실제 학부모 운영으로 바꾸려면 아래 "제외한 것"과 유료 AI·개인정보 검토가 다시 필요하다.
- **넣는 것 (기획안 15장 + 아래 2개)**
  - 선생님 답변 → 학부모 확인 (11-1장, 6장 흐름, `design/screens/ParentReply.html`, `ParentMobileReply.html`)
  - 반복 민원 처리 (9장)
- **제외한 것: 기획안의 "별도 긴급 안전 프로토콜"**
  - 고위험 사안 관리자 즉시 알림·동시 확인 절차, 근무시간 외 대응 절차
  - 2장 원칙 5의 예외("학부모가 전달하지 않아도 사전 고지한 긴급 상황이면 별도 프로토콜") → **학부모 동의 없이는 어떤 경우에도 학교에 전달하지 않는다.**
- **남기는 것: MVP 의 최소 안전장치**
  - `src/lib/ai/safety.ts`(위험 표현 → 112·119·109 먼저 안내), 상담 지침의 안전 규칙, earlierRisk. 지우지 않는다.
- **위험도 분류는 "표시"만 한다.** Level 0~3 으로 분류해 관리자 화면에 "고위험 상담"으로 보여 줄 뿐, 알림·자동 배정·대응 절차는 없다.

## 1. 단계별 계획

각 단계는 MVP 처럼 작게 나눠 만들고, 끝날 때마다 **평가 세트 문항 추가 → `npm.cmd run eval -- --runs 2` → 브라우저 확인 → GitHub push**(되돌릴 지점) 순서로 마무리한다.

### A. 흐름 완성 — 학부모 ↔ 교사 왕복 (✅ 2026-11-23 완료, 기록은 CLAUDE.md "v2 A")

| 기능 | 내용 | 참고 |
|---|---|---|
| 교사 답변 작성 | 업무함 상세에서 답변을 쓰고 보낸다. 보내면 Case 상태 `RESOLVED`(답변 완료) | TeacherInbox.html [답변 작성] |
| AI 답변 초안 | 교사가 누르면 final_summary 를 바탕으로 초안 생성. 그대로 보내지지 않고 교사가 고쳐서 보낸다. 대화 원문은 쓰지 않는다 | 기획안 10-C, TeacherInbox.html "AI 답변 초안" |
| 학부모 답변 확인 | 상담 내역에서 "선생님 답변 도착" 표시 → 답변 화면. 상태 표시 `학교 전달 완료 · 선생님 답변 도착` | ParentReply.html, DESIGN.md 2장 |
| 관리자 이관 | 교사가 [관리자와 공유] → Case `ESCALATED`, 교감·교장(ADMIN)에게 배정 | 기획안 5·6장 |

- DB(예상): `case_replies`(case_id, author_id, body, created_at) 또는 cases 에 답변 칼럼, Assignment 에 관리자 배정, 교사의 cases 상태 변경은 **함수로만**(MVP 원칙 유지).
- RLS: 학부모는 본인 Case 의 답변만, 교사는 배정+담당 학급, 관리자(ADMIN)는 이관된 Case 만. `supabase/tests/rls_check.sql` 에 문항 추가.
- 상담 가능시간 제안·신청(ParentReply.html 의 시간 선택)은 D 단계로 미룬다. A 에서는 답변 글만.

### B. 분류 — 위험도 표시·반복 민원·관리자 화면 (✅ 2026-11-24 완료, 기록은 CLAUDE.md "B")

| 기능 | 내용 |
|---|---|
| 분석·분류 AI | 학부모에게 보이지 않는 별도 호출. 문의 유형(정보/개별 상담/불만·민원/관리자 검토), 위험도 Level 0~3, 근거를 `risk_assessments` 에 기록 (기획안 7장, 10-B, 12장 RiskAssessment) |
| 위험 표현 규칙 고도화 | `safety.ts` 를 Rule Engine 으로 확장: 표현 사전 + 문맥 예외. 최종 위험도 = AI 분류 + 규칙 탐지 (11-5장) |
| 반복 민원 처리 | 같은 학부모·같은 사안의 반복 문의 감지(빈도·동일 내용·이전 답변 여부·새 사실 여부·요구 강도·욕설/협박, 9장). AI 가 먼저 이전 학교 답변을 확인시키고, 계속되면 관리자에게 "동일 사안 반복 문의" 표시. **학부모를 악성 민원인으로 분류하지 않는다** |
| 관리자 화면 | `/admin` — 이관된 사안, 고위험 상담(표시만), 익명 통계(상담 시작/AI 종료/교사 전달/관리자 확인). AdminDashboard.html |
| 교사 업무함 위험도 칩 | MVP 에서 뺀 칩을 분류 결과로 다시 표시 |

- 주의: 통계에서 학급 단위 숫자가 작으면 누가 상담했는지 짐작될 수 있다 → 교사에게는 보이지 않게 하거나 최소 건수 미만은 숨김.
- 평가 세트: 위험도 분류 정확도, 고위험 누락률·오탐률(기획안 11-7 표의 7개 예시 포함), 반복 민원 오판.

### C. 지식 — 학교 자료 근거 답변

| 기능 | 내용 |
|---|---|
| 문서 등록 | 교사·관리자가 가정통신문·학교 규정 등을 올린다(가상 문서로 시범). Supabase Storage + `documents` |
| 문서 검색(RAG) | 텍스트 추출 → 조각(`document_chunks`) → 임베딩 → **pgvector** 저장 → 질문과 비슷한 조각만 AI 에 전달 (11-3장) |
| 근거 카드 | 답변 아래 "근거 · 문서명 · 원문 보기" (SourceCard, ParentChat.html "관련 기준 안내") |
| 관련 규정 확인 | 교사 업무함 상세에서 사안 관련 규정 조각을 함께 보여 줌 |
| 교육·법률 자료 | **검증된 공식 자료만** 관리자가 등록 (13장). 일반 인터넷 검색 결과는 쓰지 않는다 |

- MVP 지침의 "학교 자료가 없으면 숫자·날짜를 지어내지 않는다"는 유지: 검색 결과가 없을 때만 그 문구.
- 임베딩 모델은 시작 전에 Gemini 무료 등급에서 쓸 수 있는 것을 직접 확인한다.

## 2. 바뀌지 않는 원칙 (MVP 에서 그대로)

- **상담 ≠ 민원 접수**: Case 는 학부모가 요약을 확인하고 동의했을 때만 생긴다.
- 권한은 화면이 아니라 DB RLS 로 막는다. secret 키는 서버에서만.
- 교사·관리자는 대화 원문을 보지 않는다. 학부모가 확인한 요약과 답변만.
- AI 는 잘잘못·아동학대 여부를 단정하지 않는다. 학교 정보는 근거가 있을 때만 말한다.
- Gemini 무료 등급 → 가상 데이터만. 실제 개인정보 금지.
- Next.js 16 은 떠난 화면을 숨겨 보관한다 → "새로 시작해야 하는 화면"은 숨겨질 때 상태를 비운다.
